# v0.8.0 입력 경계 및 민감 로그 정책

## 경계

텍스트 문서는 UTF-8 `.txt`, PDF 추출은 signature가 확인된 `.pdf`만 허용한다. extension 또는 MIME 단독 신뢰를 피하고 parser 검증을 결합한다. archive extraction, decompression, 신규 PDF/docx parser, 신규 OCR, antivirus 및 malware sandbox는 이번 범위에 포함하지 않는다.

업로드 원본 filename은 저장 경로가 아니다. PDF 원본은 repository 밖의 제한된 temp root 아래 UUID 경로에만 존재하며 request marker와 디렉터리 identity를 확인한 뒤 삭제한다. 부분 upload와 parser 실패도 동일 cleanup 경로를 사용한다.

## 로그 금지 데이터

filename, 이메일, Authorization, JWT/token, request/response body, 계약 원문, extracted text, clause body, Evidence, storage/temp path, DB URL, provider payload와 raw exception은 구조화 로그에 남기지 않는다. 허용 항목은 request ID, 안전한 event/code, status, duration, file size, content type category와 비가역 식별자에 한정한다.

rate limit bucket은 raw client address나 user ID가 아닌 SHA-256 파생 key를 사용한다. 응답과 로그에는 bucket key 자체도 노출하지 않는다.
