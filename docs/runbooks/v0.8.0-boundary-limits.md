# v0.8.0 Boundary Limits Runbook

## 필수 production 설정

`MAX_UPLOAD_BYTES`, `MAX_EXTRACTED_CHARACTERS`, `MAX_DOCUMENT_PAGES`, `RATE_LIMIT_LOGIN`, `RATE_LIMIT_REGISTER`, `RATE_LIMIT_UPLOAD`, `RATE_LIMIT_EXTRACTION`, `RATE_LIMIT_ANALYSIS_JOB`, `RATE_LIMIT_WINDOW_SECONDS`를 모두 명시한다. 값은 양의 정수여야 하며 코드의 안전 상한을 넘을 수 없다. 누락, 0, 음수, 숫자 변환 실패 또는 과도한 값은 startup을 차단한다.

Compose의 migrate, API, worker 서비스에 동일 값을 전달한다. Dockerfile에 운영 제한값을 하드코딩하지 않는다.

## 변경 절차

제한을 높이기 전에 최대 동시 메모리, 임시 디스크, DB transaction 시간, parser 처리 시간과 abuse 영향을 검토한다. 여러 API replica를 사용하는 환경에서는 process-local 요청 제한을 전역 제한으로 간주하지 않는다.

설정 변경 후 production validation, targeted boundary test, 전체 backend test와 `docker compose config`를 실행한다. 실제 image build/container smoke test 및 MySQL 연동은 별도 실행 결과가 있을 때만 검증 완료로 기록한다.

## 장애 대응

429 증가는 bucket 이름과 safe error code로 확인한다. raw IP나 user ID를 로그에 추가하지 않는다. 임시 정리 실패 시 경로나 filename을 기록하지 않고 `temporary_cleanup_failed`와 `TEMPORARY_STORAGE_ERROR`만 사용한다. 반복 실패가 발생하면 신규 upload traffic을 제한하고 temp root의 권한·용량을 운영 환경에서 별도로 점검한다.
