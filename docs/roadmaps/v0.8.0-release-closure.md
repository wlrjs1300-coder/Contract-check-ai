# v0.8.0 Release Closure

## 완료 범위

- Durable jobs: enqueue-only API, DB worker, atomic claim, lease/heartbeat, stale recovery, bounded retry와 active dedupe
- Operations: 공용 image 정의, API/worker/DB/migrate Compose 분리, health/readiness, production fail-closed, structured logging, graceful shutdown
- Boundary protection: 선택적 쓰기 API rate limit, text/PDF 크기·형식·filename 검증, PDF temp cleanup, extraction 문자·페이지 제한, 안전 오류와 관련 테스트

## 명시적 제외

Redis/distributed limiter, Kubernetes, Terraform, CI/CD 자동 배포, 외부 observability, WAF, antivirus, malware sandbox, archive extraction, 신규 OCR/PDF/docx parser, WebSocket/SSE, cancellation, billing, 관리자 UI와 신규 AI provider는 후속 범위다.

여러 API replica에서 rate limit bucket은 공유되지 않는다. 실제 Docker image/container smoke test와 실제 MySQL 연동은 실행 기록이 없으면 완료 항목으로 간주하지 않는다.

## Docker/MySQL smoke 검증

- 로컬 Docker Desktop에서 공용 이미지를 `--no-cache`로 빌드했으며, 이미지 내부에서 `PyMySQL 1.2.0`과 애플리케이션 import가 성공했다.
- MySQL 8.4 컨테이너가 healthy 상태에 도달했고, `mysql+pymysql` 연결로 Alembic migration이 exit code 0으로 완료됐다. 현재 revision은 `0006_durable_analysis_jobs (head)`다.
- API의 `/health`는 `{"status":"ok"}`, `/ready`는 `{"status":"ready"}`를 반환했다. API와 worker 모두 실행됐고 restart count는 0이며 worker polling 시작 로그를 확인했다.
- API와 worker 로그에서 자격증명 포함 DB URL, Authorization header, JWT·암호화·HMAC 키, DB 비밀번호, 계약 원문, 파일명 및 로컬 경로 노출은 발견되지 않았다.
- 호스트 TCP 3306이 이미 사용 중이어서 MySQL은 동일 Compose 서비스와 named volume을 사용하되 host port를 게시하지 않고 Compose 내부 network alias로 검증했다.
- 공용 Dockerfile의 API 전용 healthcheck를 제거하고 API 서비스의 Compose healthcheck만 유지했다. worker는 HTTP 포트를 제공하지 않으므로 별도 Docker healthcheck를 상속하지 않으며, 실제 process 실행과 polling 상태는 container 상태 및 structured log로 확인한다.
- 이 검증은 로컬 synthetic 환경의 smoke 검증이며 production 배포 자체를 검증한 것은 아니다.
