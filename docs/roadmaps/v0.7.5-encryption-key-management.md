# v0.7.5 저장 암호화·키 관리 로드맵

## 목표

v0.7.5는 저장 암호화, keyring, key rotation 기반, fail-closed 오류 계약, migration과 테스트를 실제 구현한다. 현재 문서 집합은 구현 전에 정책과 경계를 확정한다. v0.7.5 완료는 보관형 실운영이나 실제 개인정보 사용의 자동 승인을 의미하지 않는다.

## 1. 설계 확정

- A/B/C/D 필드 분류 확정
- 인증 주체와 부모 기반 owner 경계 확인
- envelope, canonical AAD, 오류 계약 확정
- filename·nested JSON·migration 미확정 항목 결정

완료 기준:

- ADR 상태와 구현 전 결정 항목 일치
- 문서 간 평문 fallback, AAD, key status 정책 일치

## 2. Crypto core 및 keyring

- keyring parsing과 strict schema 검증
- AES-256-GCM encrypt/decrypt
- Base64 strict encode/decode
- canonical AAD 생성
- 안전한 오류 코드 정규화
- key status와 active key 검증

완료 기준:

- malformed·누락·중복 keyring fail-closed
- raw key 비노출
- envelope 누락·추가·tamper 거부

## 3. Scalar 필드 암호화

- encrypted backing column 검토 및 구현
- `Clause.body`, `ExtractionPage.text`, `AnalysisResultItem.summary` 우선 적용
- B등급 filename·title·구조화 값의 API 호환성 결정
- 명시 helper를 통한 암복호화

완료 기준:

### PR-3 구현 결과 (2026-07-25)

- `ExtractionPage.extra_data`의 `reviewed_text`/`final_text`/`blocks[*].text`와 `Extraction.extra_data.confirmation_snapshot`의 `pages[*].final_text`/`pages[*].blocks[*].text`를 `backend/app/services/nested_json_encryption.py`에서 암호화·검증한다.
- evidence excerpt, 분석 자연어(요약·권고 등)는 이번 PR-3 범위에 포함하지 않았다. `AnalysisResultItem.summary`는 PR-2 scalar 암호화로 이미 처리됐고, `extra_data.analysis_value`(자연어 설명, evidence 등)는 여전히 평문으로 남아 있어 후속 범위로 이관한다.

## PR-4: analysis_value sensitive-text encryption

- Scope added in this PR: encrypt only `AnalysisResultItem.extra_data["analysis_value"]` sensitive natural language fields:
  - `title`, `risk_reason`, `practical_impact`, `recommendation`, `expert_review_summary`
  - `questions_to_ask[*].question`, `questions_to_ask[*].purpose`
  - `negotiation_suggestions[*].objective`, `.suggested_change`, `.fallback_option`
  - `extracted_facts[*].label`, `.value`
- Strict allowlist + fail-closed behavior is required for `analysis_value` payload and nested list entries.
- Plain metadata kept in cleartext for this field set: enum, severity, action_priority, offset, hash, confidence, boolean flags, evidence/reference metadata, normalized metadata.
- AAD for this PR uses:
  - resource types: `analysis_result_item`, `analysis_result_question`, `analysis_result_suggestion`, `analysis_result_fact`
  - canonical record_id: `analysis_job_id` + `clause_record_id` (+ nested item id for question/suggestion/fact)
  - field_name and schema_version `analysis-result-v1`.
- ID-based binding:
  - question/suggestion/fact ID empty or duplicate is invalid.
  - AAD includes each nested item id, so item substitution is rejected.
- This PR does not include:
  - evidence source_text/excerpt, Document.filename, Extraction.filename_display, Clause.title, key rotation, re-encryption batch helper
  - `reviewed_text/final_text` scope and other extra_data field expansions (already in PR-3)
- No separate Alembic revision is required for this PR because this is nested JSON value-shape change only.

secret custody, KMS/Vault/Secret Manager integration, production rotation, or
deployment approval. Legacy local DB import is intentionally excluded.

email lookup with limited legacy fallback, ownership-before-decryption, and a

no plaintext.

shutdown, column removal, lookup-key rotation, production backfill execution,
and operational approval remain incomplete. v0.7.5 is not complete.
