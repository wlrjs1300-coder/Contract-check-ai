## 보안·개인정보 경계

검증에는 실제 Secret, 실제 email·IP·domain, 실제 계약서, 개인정보, credential-bearing DB URL, Docker resource ID, runtime subnet, raw exception 또는 내부 로그 전문을 사용하거나 공개 문서에 기록하지 않았다. 예시 주소가 필요한 경우 예약된 `.invalid` domain만 사용한다.

v0.9.0 완료는 합성 데이터 기반 운영 경계의 재현 가능성을 뜻한다. 실제 데이터 사용은 처리 목적·법적 근거, 고지, 보존·삭제, 접근 통제, Provider 전송 조건과 독립 보안·개인정보 검토를 별도로 완료하기 전까지 허용하지 않는다.

## 릴리스 후속 절차

이 closure 문서 작성 시점에는 다음 절차가 남아 있다.

1. closure PR을 `develop`에 병합한다.
2. `develop`→`main` 정식 릴리스 PR을 병합한다.
3. main merge commit을 검증한다.
4. 검증된 commit에 v0.9.0 annotated tag를 생성하고 push한다.
5. main 릴리스 계보를 `develop`에 다시 동기화한다.

따라서 main 릴리스와 v0.9.0 tag는 아직 완료로 기록하지 않는다.
