# v0.8.0 API Boundary Protection

## 적용 API

- `POST /auth/login`: 분당 10회
- `POST /auth/register`: 분당 5회
- `POST /documents/upload`: 분당 10회
- `POST /extractions`: 분당 20회
- 문서·추출 기반 analysis job 생성: 합산 분당 10회

제한값과 window는 환경변수로 설정한다. 초과 응답은 HTTP 429이며 `Retry-After`와 기존 request ID 응답 헤더를 포함한다.

```json
{
  "detail": {
    "code": "RATE_LIMIT_EXCEEDED",
    "message": "Too many requests. Please try again later."
  }
}
```

## 업로드 및 추출

문서 업로드는 UTF-8 `.txt`와 `text/plain`만 지원한다. 0 byte, NUL, 위험한 double extension, 경로 구분자, `..`, 제어문자 및 255자를 넘는 filename은 거부한다. filename은 저장 경로로 사용하지 않는다. 문서 API 상한은 1 MiB이고 streaming chunk를 읽는 동안 제한한다.

PDF 추출은 `.pdf`와 허용 MIME 조합을 확인하고 `%PDF-` signature를 parser 경계에서 검증한다. 임시 원본은 UUID server filename으로 저장하며 성공·실패 후 request directory 전체를 정리한다. archive, 실행 파일, script 및 독립 image upload는 문서/PDF endpoint에서 지원하지 않는다. 기존 image extraction API와 OCR adapter는 별도 기존 계약을 유지하며 신규 OCR 기능은 추가하지 않았다.

기본 상한은 upload 20 MiB, 추출 문자 2,000,000자, PDF 100페이지다. text document API에는 더 낮은 1 MiB hard cap이 적용된다.

## 안정 오류

| HTTP | code | 의미 |
|---|---|---|
| 400 | `EMPTY_FILE` | 빈 업로드 |
| 400 | `INVALID_FILENAME` | 안전하지 않은 filename |
| 400/422 | `MALFORMED_DOCUMENT` | 해석할 수 없는 입력 또는 유효 텍스트 없음 |
| 413 | `UPLOAD_TOO_LARGE` | 업로드 크기 초과 |
| 413 | `EXTRACTION_LIMIT_EXCEEDED` | 문자 또는 페이지 제한 초과 |
| 415 | `UNSUPPORTED_FILE_TYPE` | extension, MIME 또는 형식 불일치 |
| 429 | `RATE_LIMIT_EXCEEDED` | 요청 제한 초과 |
| 500 | `TEMPORARY_STORAGE_ERROR` | 안전한 임시 저장소 처리 실패 |

응답에는 내부 경로, filename 전체값, DB URL, raw 예외, parser stack trace 또는 원문이 포함되지 않는다.
