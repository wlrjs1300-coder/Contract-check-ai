## PR-2 / PR-3 구현 요약 (설계 대비 실제 코드 기준)

- PR-2(`backend/app/services/scalar_encryption.py`, migration `0003_scalar_field_encryption`): `Clause.body` → `body_encrypted`, `ExtractionPage.text` → `text_encrypted`, `AnalysisResultItem.summary` → `summary_encrypted`. 세 컬럼 모두 평문 컬럼을 제거한 encrypted-only 컬럼이며, 기존 평문 컬럼과의 dual-write는 없다.
- PR-3(`backend/app/services/nested_json_encryption.py`): `ExtractionPage.extra_data`의 `reviewed_text`, `final_text`, `blocks[*].text`와 `Extraction.extra_data.confirmation_snapshot`의 `pages[*].final_text`, `pages[*].blocks[*].text`를 각각 `*_encrypted` envelope로 치환. 상태·버전·ID·ordinal·confidence·bbox·reading_order·checksum·hash·boolean 등 비민감 metadata는 평문 유지. `extra_data` 전체를 투명 암호화하지 않는다.
- 세부 필드별 allowlist와 dual-write/legacy fail-closed 검증은 `nested_json_encryption.py`가 전담하며, `clause_splitter.py`/`evidence_linking.py`는 복호화된 평문 snapshot만 전달받아 기존 알고리즘을 그대로 사용한다.
- migration: nested JSON 구조 변경은 기존 JSON 컬럼(`extra_data`) 내부 스키마만 바꾸므로 별도 Alembic revision을 추가하지 않았다. 대신 decrypt 경로에서 legacy plaintext 형태(예: `reviewed_text` 키가 non-null로 남아있는 row)를 만나면 fail-closed(`ScalarDecryptionError`)로 처리한다. 합성 개발 DB 초기화를 전제로 하며, `contract_check.db`를 자동으로 수정하거나 삭제하지 않는다.
- PR-3에서 함께 수정한 PR #74 이후 회귀:
  - `evidence_linking.bind_evidence_to_finding()`가 `getattr(clause, "body", "")`에 의존하던 문제를 제거하고 `source_text`를 명시적 파라미터로 받도록 변경. `run_analysis_pipeline()`이 clause body를 한 번만 복호화해 `build_provider_input()`과 `bind_evidence_to_finding()` 양쪽에 전달한다.
  - `confirm_extraction()`에서 `page_data["review_status"] = "confirmed"`를 먼저 실행한 뒤 `"edited"` 여부를 확인하던 순서 버그를 수정. edited 여부를 상태 변경 전에 저장해 confirmation 이후 page-level `final_text`/`final_text_preview`가 원본 텍스트로 되돌아가지 않도록 함.
  - `run_analysis_pipeline()`이 `Document.owner_id`를 확인하기 전에 confirmation snapshot을 조회하던 순서를 owner 확인 → snapshot 복호화 순서로 재정렬. `_load_confirmation_snapshot()`은 `extraction.owner_id`가 전달된 `owner_id`와 다르면 빈 snapshot으로 처리한다.

## Envelope와 AAD

```json
{
  "enc_version": 1,
  "key_id": "synthetic-key-v1",
  "algorithm": "AES-256-GCM",
  "nonce": "...",
  "ciphertext": "..."
}
```

- `nonce`는 Base64로 인코딩한다.
- `ciphertext`는 AESGCM이 반환한 ciphertext와 authentication tag의 결합 payload 전체를 Base64로 인코딩한다.
- plaintext AAD는 envelope에 저장하지 않는다.
- `algorithm`, `enc_version`, `key_id`는 엄격한 타입·allowlist 검증을 거친다.
- envelope의 누락 필드와 추가 필드는 기본적으로 fail-closed 처리한다.
- AAD는 서버가 신뢰 가능한 DB 관계와 호출 context에서 deterministic canonical encoding으로 재생성한다.
- 권장 구성은 `resource_type`, `record_id`, `field_name`, `owner_id`, `schema_version`이다.
- canonical JSON은 UTF-8, key 정렬, 불필요한 공백 제거, 타입 변환 금지, 누락 값 금지 규칙을 따른다.

## `extra_data` 구현 기준

v0.7.5 구현에서는 모델별·schema별 allowlist와 validator를 도입한다. 현재 임의 key 금지는 `ExtractionPage.extra_data`의 `reviewed_text`/`final_text`/`blocks[*].text`와 `Extraction.extra_data.confirmation_snapshot`의 `pages[*].final_text`/`pages[*].blocks[*].text` 범위에서만 구현 완료 상태이며(`backend/app/services/nested_json_encryption.py`), `extra_data` 전체 key에 대한 allowlist는 아직 없다.

- 평문 운영 메타데이터: 상태 전이, 동시성, checksum, 관찰성, 생명주기 관리에 필요한 version, status, count, boolean, hash, code
- 암호화 대상 민감 하위 필드: snapshot, reviewed/final text, blocks text, 분석 자연어, evidence excerpt, raw/source fact text, 검토 요약과 실행 제안
- 저장 금지: raw Provider payload, raw token mapping, 마스킹 전 전체 복사본, raw PII, Secret, token, Authorization header, 내부 경로, 임시 이미지, 중복 원문, 디버깅 payload

전체 `extra_data`를 투명하게 한 번에 암호화하지 않는다.

### Nested JSON AAD 실제 구성 (PR-3 구현 기준)

Envelope는 scalar 필드와 동일한 `{enc_version, key_id, algorithm, nonce, ciphertext}` 형태를 그대로 재사용하되, JSON 컬럼 내부에 저장되므로 문자열이 아니라 dict(mapping)로 저장한다. `schema_version`은 `nested-json-v1`을 사용한다.

| 대상 | `resource_type` | `record_id` 구성 | `field_name` |
| --- | --- | --- | --- |
| `ExtractionPage.extra_data.reviewed_text` / `final_text` | `extraction_page_extra` | `{extraction_id, page_number}` | `reviewed_text` 또는 `final_text` |
| `ExtractionPage.extra_data.blocks[*].text` | `extraction_page_block` | `{extraction_id, page_number, block_index}` | `text` |
| `confirmation_snapshot.pages[*].blocks[*].text` | `confirmation_snapshot_block` | `{extraction_id, snapshot_version, page_number, block_index}` | `text` |
| `confirmation_snapshot.pages[*].final_text` | `confirmation_snapshot_page` | `{extraction_id, page_number, snapshot_version}` | `final_text` |

- block AAD는 `block_index`(OCR 결과 순번)만 사용한다. `block_id`는 `clause_splitter.py`가 나중에 생성하는 값이라 저장 시점에 확정되지 않으므로 AAD에 포함하지 않는다.
- `ExtractionPage.extra_data.blocks[*].text`와 `confirmation_snapshot.pages[*].blocks[*].text`는 **서로 다른 `resource_type`(`extraction_page_block` vs `confirmation_snapshot_block`)과 서로 다른 `record_id`(snapshot 쪽은 `snapshot_version` 추가 포함)를 사용해 암호학적으로 분리했다.** 동일 `extraction_id`/`page_number`/`block_index`라도 한 저장 위치의 ciphertext를 다른 위치에 복사하면 AAD mismatch로 복호화가 실패한다(`nested_json_encryption.encrypt_confirmation_snapshot_blocks`/`decrypt_confirmation_snapshot_blocks`). confirm 시점에 block을 재암호화하므로 페이지 생성 시점의 ciphertext와 confirm 시점의 ciphertext는 값도 다르다(중복 ciphertext 재사용 없음).
- `confirmation_snapshot.pages[*].final_text`와 `confirmation_snapshot.pages[*].blocks[*].text` 모두 `snapshot_version`을 AAD에 포함해, 다른 snapshot 세대의 ciphertext가 실수로 섞여 들어가도 복호화가 실패하도록 했다. `ExtractionPage.extra_data.final_text`/`blocks[*].text`는 페이지 단위 값이라 `snapshot_version`을 포함하지 않는다.
- `reviewed_text`/`final_text`가 동일 내용을 중복 저장하는 기존 구조는 이번 PR에서 유지했다(각각 독립적으로 암호화). 구조 단순화·중복 제거는 후속 작업으로 남겼다.
- decrypt 경로에서 legacy 평문 key(`reviewed_text`, `final_text`, block의 `text`, snapshot page의 `final_text`)가 non-null로 남아 있으면 `ScalarDecryptionError`로 fail-closed 처리한다(§`nested_json_encryption.read_extraction_page_text_field`/`decrypt_extraction_page_blocks`/`decrypt_confirmation_snapshot`).
- owner 검증 순서: `run_analysis_pipeline()`은 `Document.owner_id`를 확인한 뒤에만 confirmation snapshot을 복호화한다. `_load_confirmation_snapshot()`은 조회된 `Extraction.owner_id`가 전달받은 owner와 다르면 즉시 빈 snapshot으로 처리한다(복호화 시도 자체를 하지 않음).

## 테스트 계획

### Keyring

- 누락·malformed JSON·중복 `key_id`·active key 불일치
- malformed Base64·31-byte·33-byte key·unsupported status
- decrypt-only key의 신규 encrypt 거부와 retired key 실패
- raw key의 app state 미저장

### Envelope와 암복호화

- round trip과 nonce에 따른 ciphertext 차이
- ciphertext/authentication tag·nonce tamper
- unknown `key_id`, unsupported version, algorithm mismatch
- 필드 누락·추가 필드·malformed Base64
- 한글 Unicode, 빈 문자열, 대용량 텍스트, null byte 정책
- double encryption 방지

### AAD와 저장 경계

- 잘못된 resource, record, field, owner, schema version 거부
- 외부 입력 AAD를 신뢰하지 않고 서버 재구성값 사용
- 다른 row로 ciphertext 복사 시 복호화 실패
- A등급 필드와 민감 JSON 하위 필드의 raw DB 평문 검색 실패
- ORM/API 정상 복호화와 production 평문 fallback 거부
- 평문과 암호문 동시 저장 거부

### Rotation과 비노출

- active key 신규 쓰기, decrypt-only 기존 읽기와 신규 쓰기 거부
- 새 active key 전환, 점진 재암호화, idempotency, retired key 실패
- 예외·응답·로그에 raw key, 평문, ciphertext, nonce, 환경변수 원문 미노출
- cross-user API `404` 유지
